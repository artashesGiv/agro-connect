# Спецификация приложения

## Назначение

Базовая заготовка конкурсного Android-приложения. Конкретную идею, аудиторию и основной пользовательский сценарий нужно описать здесь до разработки функций.

## Текущая версия

- Гейт авторизации при входе: если пользователь не авторизован — экраны
  «Вход» / «Регистрация»; после входа — табы.
  - «Вход» — форма с валидацией (email + пароль) на react-hook-form + zod.
  - «Регистрация» — мастер из 3 шагов: почта → имя / специализация / регион →
    пароль и повтор. Валидация react-hook-form + zod. Сеть трогает только
    последний шаг: `signUp` создаёт аккаунт и сразу заполняет `profiles`.
    Подтверждение почты на бэкенде отключено, поэтому сессия появляется ещё до
    записи профиля — от преждевременного перехода в табы защищает отдельное
    состояние `registering` у `AuthStatus`.
  - Сессию хранит сам Supabase SDK в `AsyncStorage`; при старте она
    восстанавливается без сети.
  - Сессия (`status` / `user` / `profile`) — в контекст-сторе `AuthProvider`
    (`src/services/auth`), источник правды — `supabase.auth.onAuthStateChange`.
  - Выход — кнопка «Выйти» на вкладке «Профиль»; там же показываются имя,
    специализация, регион, репутация и аватар из таблицы `profiles`.
- Нижняя навигация — 5 вкладок:
  - **Главная** — интерактивный счётчик для проверки состояния
  - **Карта** — карта 2GIS (MapGL) с переходом на местоположение пользователя;
    подробности — в разделе «Карта»
  - **«+»** (центральная крупная кнопка) — заглушка (будущее создание)
  - **«?»** — временная вкладка-заглушка
  - **Профиль** — данные из `profiles` (имя, специализация, регион, репутация,
    аватар), почта из сессии и кнопка «Выйти»
- Полная типизация TypeScript для навигации
- Портретная ориентация
- Safe area: приложение рисуется edge-to-edge, экраны без шапки обёрнуты в
  `Screen` / `KeyboardAwareScreen`; на вкладках верх закрывает шапка, низ —
  таб-бар
- Формы: при фокусе поле выводится в центр области над клавиатурой
- UI на React Native Paper (Material Design 3); единая светлая тёплая тема
  «пшеница + кофе», палитра в `src/theme/theme.ts` — цвета меняются в одном месте

## Карта

Вкладка «Карта» — карта 2GIS и ничего больше: ни меток, ни карточек объектов,
ни детального просмотра.

**Как устроено.** MapGL JS API 2GIS внутри `react-native-webview`; сам MapGL
подгружается тегом `<script>` с `mapgl.2gis.com`, npm-пакета `@2gis/mapgl` в
зависимостях нет. Ключ — `EXPO_PUBLIC_2GIS_MAPGL_KEY` в `.env` (в `.env.example`
только плейсхолдер: ключ MapGL, в отличие от publishable key Supabase, не
прикрыт ничем, и утёкший ключ означает выжженный лимит запросов). Код —
`src/features/map/`: `components/mapHtml.ts` (страница + протокол сообщений),
`components/MapGLView.tsx` (WebView, спиннер, ошибка, `flyTo`),
`hooks/useCurrentLocation.ts`, `screens/MapScreen.tsx`.

**Почему WebView, а не нативная карта.** Официального React Native SDK у 2GIS
нет — в npm-организации `@2gis` только веб-пакеты, нативный Mobile SDK
существует для Android/iOS/Flutter. Свой нативный модуль потребовал бы
config-плагина и custom dev client, то есть приложение перестало бы
открываться в Expo Go. `react-native-maps` (Google Maps) был бы проще на
кастомных метках, но это не 2GIS; `expo-maps` официально в alpha и тоже не
работает в Expo Go. Плата за WebView: карта не работает офлайн совсем, а
кастомные метки придётся рисовать HTML внутри страницы, а не JSX c Paper.

**Спутник отложен намеренно.** 2GIS не поставляет спутниковую подложку: в
MapGL её можно добавить через `mapgl.RasterTileSource`, но снимки нужно взять
у стороннего провайдера (MapTiler / Mapbox / Esri) и лицензировать самому,
плюс это второй ключ и второй биллинг. И как только спутник включён, векторная
подложка 2GIS под ним не видна — значит нужен переключатель «Схема / Спутник».
Всё это добавляется вместе с полями, а не раньше.

**Геолокация** (`expo-location`, работает в Expo Go; config-плагин не нужен —
модуль сам добавляет разрешения в манифест):

- Камера едет на пользователя при **каждом** появлении вкладки, перелёт
  анимированный.
- Позиция берётся сначала из кеша ОС (мгновенно), затем уточняется реальным
  фиксом с точностью `Balanced` (~100 м). Поэтому камера может доехать в два
  приёма: второй обычно смещает её на десятки метров.
- У `getCurrentPositionAsync` нет своего таймаута, ограничение в 8 секунд
  сделано гонкой промисов.
- Разрешение просим точное (`ACCESS_FINE_LOCATION`), хотя точность замера пока
  `Balanced`: поднять её под будущие поля можно будет без нового системного
  диалога.
- Нет позиции (отказ, выключен GPS, таймаут) — карта остаётся там, где
  открылась: Москва `[37.6173, 55.7558]`, зум 10. Камеру туда не возвращаем
  повторно, чтобы не сбрасывать то, что человек рассматривает. Предупреждение
  показывается снекбаром один раз за запуск приложения.

**Элементы управления.** Зум-контрол 2GIS встроенный (`zoomControl`, по
умолчанию `topRight`). Копирайт 2GIS убрать нельзя, поэтому он перенесён в
`bottomLeft`, чтобы не пересекаться с кнопкой «моё местоположение» —
RN-компонентом Paper в `bottomRight`. Вращение и наклон карты жестами
выключены: компаса нет, и вернуть север после случайного жеста было бы нечем.

**Известные ограничения.** Ключ демонстрационный и истекает примерно через
месяц после выпуска — тогда карта уйдёт в состояние ошибки с кнопкой
«Повторить», это не поломка кода. Ключ MapGL может быть ограничен по домену,
поэтому страница отдаётся WebView с `baseUrl: 'https://localhost'` вместо
`about:blank`; если ключ привязан к другому домену, менять надо
`MAPGL_BASE_URL` в `MapGLView.tsx`.

### Поля пользователя на карте

Вкладка показывает свои поля (`fields`) и позволяет добавлять новые. Чужих
полей не существует с точки зрения клиента: RLS отдаёт только свои, а
`owner_id` при вставке проставляет сам клиент — сервер этого не делает.
Совместного доступа к полю схема не поддерживает вовсе.

- **Чтение геометрии** идёт через `Accept: application/geo+json` (метод
  `.geojson()` у `postgrest-js`): PostgREST сам зовёт `st_asgeojson`.
  Запросов два — по одному на `center` и на `boundary`, потому что поведение
  при двух геометрических колонках в одном запросе не документировано.
- **Запись геометрии** — EWKT `SRID=4326;POINT(...)` / `POLYGON((...))`.
  Голый WKT дал бы SRID 0 и был бы отвергнут колонкой `geometry(...,4326)`.
- **Два способа добавить поле:** «Поставить точку» — неподвижный прицел в
  центре экрана, карта двигается под ним; «Обвести контур» — рисование
  полигона. Для контура дополнительно считается площадно-взвешенный центроид и
  пишется в `center`, чтобы у каждого поля была точка для перелёта камеры и
  будущей кластеризации.
- **Рисовалка** — `terra-draw` + официальный адаптер `@2gis/mapgl-terra-draw`,
  оба с **unpkg** с точным пином версии, в headless-режиме (свой UI, кнопки
  Paper в теме приложения). Именно unpkg, а не jsDelivr: UMD-сборка адаптера
  лежит в файле `.cjs`, jsDelivr отдаёт такой как `application/node` с
  `nosniff`, и WebView отказывается его исполнять. Подгружаются **лениво**, по
  нажатию «+»: 249 КБ на каждое открытие карты того не стоят. Включён
  `ValidateNotSelfIntersecting`. Минимальную площадь не проверяем — неудачный
  порог отрезал бы реальные участки.
- **Три фазы создания**, у каждой своя подсказка и свой набор кнопок на
  компактной центрированной плашке:
  1. `point` — прицел в центре, карта двигается под ним. «Отмена» ·
     «Поставить здесь».
  2. `drawing` — тап ставит вершину, протяжка **всегда** панорамирует карту
     (`editable` у режима полигона намеренно **не** включён). «Отмена» ·
     «Шаг назад» · «Готово».
  3. `editing` — контур замкнут, режим переключён на `TerraDrawSelectMode`,
     поэтому второй объект создать нечем. «Отмена» · «Начать заново» ·
     тумблер · «Готово».
- **Undo в terra-draw opt-in.** Без `undoRedo: { modeLevel: … }` в
  конструкторе `canUndo()` всегда `false` и «Шаг назад» — гарантированный
  no-op. Нужен именно `modeLevel`: он убирает последнюю поставленную точку и
  действует только пока фигура рисуется. Поэтому в фазе правки та же кнопка
  становится «Начать заново» (стереть контур и вернуться к рисованию), а не
  «отменить перетаскивание».
- **Тумблер «двигать карту / править точки»** в фазе правки. Перетаскивание
  вершины и панорамирование начинаются одним жестом, и надёжно развести их
  можно только явным переключателем: в положении «править» карта
  заблокирована. Фаза правки всегда начинается в положении «двигать карту»,
  чтобы не встречать пользователя неподвижной картой. У выделенной фигуры
  тащатся вершины и серединки рёбер (`midpoints.draggable` добавляет вершину),
  а сам полигон целиком — нет: случайное движение не должно унести поле в
  другой район. `selectFeature(id)` вызывается сразу при входе в фазу, иначе
  сначала пришлось бы тапнуть по собственному полигону. Событие `finish`
  terra-draw шлёт не только на замыкание контура, но и после каждого
  перетаскивания вершины, поэтому переход в фазу правки сделан одноразовым —
  иначе тумблер сбрасывался бы сам после первого же сдвига точки.
- Явного «завершить фигуру» у terra-draw нет, поэтому «Готово» забирает
  полигон из его хранилища (`getSnapshot`), берёт **первый** (если второй
  всё-таки возник — сохранить надо тот, что рисовали), убирает повторы вершин
  и требует минимум три. «Готово» работает и в фазе рисования: замыкание тапом
  по замыкающей точке — недокументированный жест, и без этого выхода
  пользователь застревал бы.
- **Обход бага адаптера 0.4.0.** В нём и `setDoubleClickToZoom`, и
  `setDraggability` сводятся к `map.blockInteraction()` /
  `unblockInteraction()` (первый — из-за копипасты со второго). terra-draw
  зовёт первый на старте режима, второй — на каждом `pointerup`, так что
  интерактивность карты менялась сама собой: карта замирала во время
  рисования, оставалась замороженной после него, а тумблер правки работал бы
  через раз. Оба метода заглушены на экземпляре адаптера, `blockInteraction`
  вызывается только из нашего `setEditInteraction`. Цена — во время рисования
  остаётся живым зум по двойному тапу.
- **Отображение:** есть контур — полигон, иначе точка. Без подписей и без
  тапа по полю. Фильтр слоя полигонов записан документированной формой
  `['match', ['sourceAttr', …], […], true, false]` — оператор `==` против
  `source-attr` проходит типизацию, но полигоны с ним не рисуются.
- Вкладка «Карта» — единственная с `lazy: false` в `MainTabs`: WebView с
  картой поднимается секунду-другую, и делать это в момент перехода значит
  показывать спиннер при каждом заходе. Поля тянутся в эффекте монтирования,
  первый фокус их не перезапрашивает.
- **Форма** — Paper `Dialog` (первый в проекте) с названием (обязательное,
  2–60 символов, автоподстановка «Поле N») и регионом, предзаполненным из
  `profiles.region`. Ошибка сохранения показывается в самом диалоге, а
  нарисованная геометрия **не сбрасывается**: обводить поле заново из-за
  пропавшей сети — худшее, что можно предложить.
- В режиме создания автоцентрирование на пользователе отключено, кнопки «+» и
  рецентра скрыты, системная «назад» выходит из режима.

`crops` на бэкенде пуста, поэтому выбора культуры в форме нет — добавим, когда
справочник наполнят.

## Бэкенд — Supabase

Бэкенда своего нет: всё хранится в размещённом Supabase-проекте. Описание схемы
приходит от бэкенд-команды в `api-docs/` (`SUPABASE_CURRENT_SCHEMA.md`,
`SUPABASE_REACT_NATIVE_QUICKSTART.md`, `database.types.ts`).

Что уже подключено на клиенте:

- `@supabase/supabase-js` + `@react-native-async-storage/async-storage`;
  единственный клиент — `src/services/supabase/client.ts`.
- Ключи — в `.env` (`EXPO_PUBLIC_SUPABASE_URL`,
  `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`); `.env.example` содержит те же
  значения. Publishable key рассчитан на мобильный клиент; `service_role` на
  фронт не попадает никогда.
- Типы схемы — `src/types/database.types.ts`, обновляются `npm run types:supabase`.
- Авторизация: вход и регистрация по паролю. Подтверждение почты на бэкенде
  выключено (`mailer_autoconfirm: true`) — писем приложение не отправляет
  и не ждёт.
- Данные: справочники (`post_types`, `post_stages`, `post_statuses`,
  `reaction_types`, `crops`), `profiles`, `fields`, лента `posts` с join'ами,
  Storage (`avatars` — публичный, `post-media` — приватный, со signed URL).
- Доступ к данным ограничен RLS: пользователь видит только свои поля, правит
  только свой профиль и свои посты.

Ещё не обёрнуто намеренно (тривиальные insert/delete, пишутся вместе с экраном):
`post_reactions`, `answers`, `answer_votes`.

## Открытые вопросы к бэкенду

Пункты 3-4 блокируют будущие экраны; 1-2 — про надёжность аккаунтов.

1. **Site URL остался дефолтным `http://localhost:3000`.** Для текущего флоу
   некритично (писем нет), но сломает восстановление пароля, если оно
   понадобится. Тогда же придётся вернуть шаблоны писем и подключить свой SMTP:
   встроенный отправщик Supabase ограничен парой писем в час.
2. **Почта никем не проверяется.** Подтверждение отключено, поэтому
   зарегистрироваться можно на любой несуществующий адрес, а восстановить
   доступ к такому аккаунту нельзя. Решение осознанное (сроки конкурса) —
   если это не так, скажите, вернём OTP-флоу.
3. **Чтение геометрии `fields.center` / `fields.boundary` — больше не блокер.**
   PostgREST отдаёт PostGIS-колонки как hex EWKB (в сгенерированных типах они
   `unknown`), но с заголовком `Accept: application/geo+json` он сам зовёт
   `st_asgeojson` и возвращает `FeatureCollection`. Клиент так и читает
   (`.geojson()` в `fieldsRepository`), отдельный view не понадобился.
   Просьба остаётся в силе как «было бы чище»: view позволил бы взять обе
   геометрии одним запросом вместо двух и дал бы типы вместо ручного разбора
   ответа.
4. **Таблица `crops` пуста** — выбор культуры в UI будет пустым списком.
5. **Начисление репутации не реализовано** — `profiles.reputation` всегда `0`.
6. Профиль хранит только `name` / `specialization` / `region`. Если продукту
   нужны фамилия и никнейм — это изменение схемы на стороне бэкенда.

## Требования, которые нужно уточнить

- Название и задача конкурсного приложения.
- Обязательные экраны и сценарии.
- Версия Android и устройство жюри.
- Допустимость React Native, Expo, сети и внешних API.
- Нужен ли подписанный release APK и есть ли ограничение размера.

## Критерии готовности

- `npm run check` завершается успешно.
- APK (профиль `preview`) устанавливается на чистое физическое Android-устройство.
- Приложение запускается после перезагрузки устройства и без dev-сервера.
- С сохранённой сессией приложение открывается сразу в табы без сети.
- Регистрация проходит целиком: аккаунт создаётся, профиль сохраняется,
  приложение сразу переходит в табы.
- Вкладки нижней навигации работают без сети.
- Сборка preview создаёт устанавливаемый APK.
