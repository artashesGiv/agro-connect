# Спецификация приложения

## Назначение

Базовая заготовка конкурсного Android-приложения. Конкретную идею, аудиторию и основной пользовательский сценарий нужно описать здесь до разработки функций.

## Текущая версия

- Гейт авторизации при входе: если пользователь не авторизован — экраны
  «Вход» / «Регистрация»; после входа — табы.
  - «Вход» — форма с валидацией (email + пароль) на react-hook-form + zod.
  - «Регистрация» — мастер из 4 шагов: почта → код подтверждения (мок, любой ввод)
    → имя / фамилия / никнейм → пароль и повтор. Валидация react-hook-form + zod.
  - Токен хранится в `expo-secure-store`, восстанавливается при старте без сети.
  - Сессия (`status` / `user`) — в контекст-сторе `AuthProvider` (`src/services/auth`).
  - Запросы идут на конфигурируемый `EXPO_PUBLIC_API_URL` (по умолчанию — тестовый
    JSONPlaceholder; ответ пока не используется, слой готовится под свой бэкенд).
  - Выход — по иконке настроек (шестерёнка) на вкладке «Профиль» (временно, до
    появления экрана настроек).
  - Модель `user` содержит поля профиля (имя, фамилия, никнейм, специализация,
    регион, телефон) — при регистрации не запрашиваются, заполнятся позже.
- Нижняя навигация — 5 вкладок:
  - **Главная** — интерактивный счётчик для проверки состояния
  - **Карта** — заглушка (будущая карта полей)
  - **«+»** (центральная крупная кнопка) — заглушка (будущее создание)
  - **«?»** — временная вкладка-заглушка
  - **Профиль** — шапка (уведомления / @ник / настройки), карточка профиля
    (аватар + имя, специализация, регион, телефон; плейсхолдеры, если не
    заполнено — общий компонент `src/components/ProfileInfo`, тот же для чужих
    профилей позже), переключатель «Мои посты / Закладки»
    - «Мои посты» — список постов: при заходе фейковый запрос → моковые данные
      (`src/services/posts`). Карточка поста — общий компонент
      `src/components/PostCard` (аватар + @ник, заголовок, описание, фото,
      кнопки: палец вверх / коммент / закладка / карта — пока без действий), тот
      же для чужих постов.
- Полная типизация TypeScript для навигации
- Портретная ориентация
- Экраны без навигационного хедера (вход, шаги регистрации, главная) обёрнуты в
  `src/components/ScreenContainer` — safe-area врезки (Android edge-to-edge всегда
  включён) плюс `KeyboardAvoidingView` для форм, чтобы статус-бар и клавиатура не
  перекрывали контент на устройствах с высокой плашкой (например Samsung One UI)
- UI на React Native Paper (Material Design 3); единая светлая тёплая тема
  «пшеница + кофе», палитра в `src/theme/theme.ts` — цвета меняются в одном месте

## Требования, которые нужно уточнить

- Название и задача конкурсного приложения.
- Обязательные экраны и сценарии.
- Версия Android и устройство жюри.
- Допустимость React Native, Expo, сети и внешних API.
- Нужен ли подписанный release APK и есть ли ограничение размера.

## Критерии готовности

- `npm run check` завершается успешно.
- APK (профиль `preview`) устанавливается на чистое физическое Android-устройство.
- Приложение запускается после перезагрузки устройства и без dev-сервера.
- С сохранённым токеном приложение открывается сразу в табы без сети.
- Вкладки нижней навигации работают без сети.
- Сборка preview создаёт устанавливаемый APK.
